### 2. 왜 이 데이터인가

- **계기**: 이커머스 데이터분석가로 커리어를 시작하려는 목표에 맞춰 "고객 불만족 조기경보" 문제를 다뤄보고 싶었음. 정형 트랜잭션 데이터만으로 배송 지연·저평점을 예측할 수 있는 한계를 먼저 확인하고, 그 예측이 놓치는 불만족의 원인을 리뷰 텍스트로 보완 설명할 수 있는지 검증하는 것이 목표.
- **조기경보 활용 시나리오**: Olist 고객 응대팀이 예상 도착일 전에 저평점 위험 주문 목록을 받아 먼저 연락하거나 보상 쿠폰을 보낸다.
- **비교한 다른 데이터셋 후보**

| 후보 데이터셋 | 제외한 이유 |
|---|---|
| Online Retail II UCI | 리뷰/평점, 배송일/도착일 컬럼이 없어 배송 요인을 X로 만들 수 없음 |
| Amazon Fine Food Reviews | 리뷰·평점만 있고 주문·배송·판매자 정보가 없어 "배송 지연에 어떤 요인이 기여하는가"라는 1단계 질문에 필요한 X를 만들 수 없음 |

- **고른 이유**: 정형 트랜잭션 데이터와 텍스트 리뷰를 동시에 갖춘 후보가 이것뿐이었고, "정형변수 기반 예측의 한계를 텍스트로 보완 설명할 수 있는가"라는 질문에 필요한 변수가 실제로 존재함.

### 3. 무엇을 분석할 것인가

- **한 문장 요약**: 주문 승인 시점에 알 수 있는 정보로 저평점 위험 주문을 골라내고, 배송 지연과 연관된 변수를 파악한 뒤, 경보가 놓치는 불만 유형을 리뷰 텍스트로 분석한다. *(수정: "예상 도착일 전" → "주문 승인 시점" — 핵심질문 2단계와 예측 시점을 일치시킴)*

- **핵심 질문**
  1. (1단계) 배송 지연 여부(실제도착일이 예상도착일보다 늦었는가)에 어떤 요인이 중요하게 기여하는가?
  2. (2단계) **주문 승인 시점(order_approved_at)에 알 수 있는 정보만으로** 저평점(1～2점) 위험을 사전 예측할 수 있는가? *(수정: "예측 시점(주문～배송 완료 전)" → "주문 승인 시점(order_approved_at)" — "배송 완료 전"에는 예상 도착일이 지난 뒤도 포함되어 한 문장 요약과 시점이 어긋나 있었음)*
  3. (3단계, 필수) 1단계 Y=0(비지연)이면서 2단계 Y=1(저평점)인 주문의 원인은 리뷰 텍스트로 무엇을 알 수 있는가? 3단계는 예측 모델이 아니라 경보가 놓친 불만 유형을 사후적으로 분석하는 단계이다. **필수 작업**은 위 대상(1단계 Y=0 & 2단계 Y=1 & 코멘트 존재, 좁은 집합)의 리뷰를 읽고 불만 원인을 분류하는 것이다. **선택 작업**은 이와 별개로, 코멘트가 있는 전체 서브셋(**40.51%, 배송완료+리뷰존재 주문 기준**, 넓은 집합) *(추가 수정 ⑪: 40.6% → 40.51%, 4절 추가 수정 ⑩과 통일)* 안에서 정형 단독 모델과 정형+텍스트 결합 모델의 성능을 비교하는 것이다(5절).

- **문제 유형**: ☑ 분류. 회귀는 Y(예측오차) 분포가 대부분 음수라 로그변환이 불가능해 지연 여부 이진 분류로 대체(4절). 군집·시계열은 핵심 질문과 직접 연결되지 않아 제외, 셀러 군집은 5절 선택 과제로만 진행.

- **목표변수 Y**
  - (1단계) 지연 여부 = 1[실제도착일(날짜) − 예상도착일(날짜) > 0] / 이진 범주형. **날짜(자정) 기준으로 정의** — 도착일시에 시:분:초가 포함되어 있어 그대로 비교하면 "몇 시에 왔는지"를 재는 셈이 되는데, 고객이 체감하는 건 "그날 왔는지"이므로 시각은 버리고 날짜 단위로 비교함(수치 크기와 무관하게 성립하는 정의상 판단). Y=0은 정시 도착이 아니라 "지연 아님(조기+정시 포함)"을 뜻함(4절 참조 — 조기 도착이 91.9%로 대다수). **지연 비율(Y=1 비중)은 조기도착 91.9%+정시도착 1.3%를 제외하면 약 6.8%로 소수 클래스임** → **class_weight='balanced' 적용, 평가지표는 혼동행렬/PR-AUC 사용**
  - (2단계) review_score 이진화(1～2점=1) / 이진 범주형

| product_category_name | 상품 카테고리 (주문 건수 상위 카테고리 + Other, 결측·미등록은 "미상" 별도) | 1·2단계 공통 | 카테고리별 배송·품질 기대수준 상이. **주문 건수 기준(threshold)으로 상위 카테고리를 정하며**, 컷오프 값은 카테고리별 실제 분포를 봐야 정할 수 있어 **1주차에 확정** |
| purchase_month | 주문 월. **1\~12 정수값으로 인코딩**(연-월 문자열로 넣으면 테스트 기간의 값이 학습 데이터에 없어 모델이 처리 못함) — 1주차 월별 추이 그래프를 본 뒤 "성수기 여부(예: 11\~12월=1)" 같은 0/1 더미로 단순화할 수도 있음. *(수정: 인코딩 형식 미기재 → 명시)* | 1·2단계 공통 | 성수기 교란변수. 분석기간이 20개월이라 테스트 기간(2018년)에는 11～12월 데이터가 없어 일반화 성능은 검증 범위 밖(한계로 명시) |

> **estimated_delivery_days는 X에서 제외.** Y(지연 여부)가 이 변수로 정의되므로(실제도착일−예상도착일) 함께 넣으면 정보 누수. **배송오차(실제도착일−예상도착일)와의 상관계수는 −0.50**, distance_km과의 상관계수는 0.52로 둘 다 상관 있어 다중공선성 우려도 있음(강사님이 전체 데이터 기준으로 확인해주신 값 — **1주차에 분석 기간으로 제한한 데이터로 재확인 예정**). *(수정: "예상오차(−0.50)"라는 표기가 다른 개념(예상소요일)과 헷갈릴 수 있어 "배송오차와의 상관계수"로 명확화. **단, 강사님 코멘트 "오차 −0.5는 표기 오류로 보입니다"의 정확한 취지는 다음 미팅 때 재확인 필요** — 표기 자체의 오류인지, 이 문구의 모호함을 지적한 것인지 확실치 않음)*

> **order 단위 집계 정책**: Y는 주문 1건당 1개인데 price·category·seller·distance는 item 단위라 대표 지정이 필요함(한 주문에 아이템·셀러가 여러 개인 경우 존재 — order_items가 order 1건당 여러 행일 수 있는 1:N 구조이므로 실제 비중과 무관하게 규칙이 필요함). 규칙:
> - **price·freight_value**: 주문 내 아이템 금액 **합산**
> - **product_category_name**: 주문 내 **결제금액(price)이 가장 큰 아이템**을 대표로 지정("가장 비싼 아이템 = 이 주문의 주력 상품"이라는 가정)
> - **seller_id·distance_km(및 seller_avg_delay)**: "어느 아이템이 비쌌는가"가 아니라 "어느 셀러가 멀리서/느리게 보냈는가"가 지연의 원인이므로, 가격 기준과 다르게 **아이템 중 최장 거리(distance_km 최댓값)를 낸 셀러**를 대표로 지정
> - **payment_installments**: order_payments도 한 주문에 여러 결제 레코드(바우처+카드 분할 등)가 있을 수 있음. boleto·voucher·debit_card는 할부 개념이 없어 값이 항상 1이므로, **주문 내 전체 결제 레코드 중 payment_installments 최댓값**을 사용하면 신용카드 결제 주문·미사용 주문 모두 예외처리 없이 자연스럽게 처리됨
> - 두 대표 지정 기준(가격 기준 vs 거리 기준)이 서로 다른 아이템을 가리키는 경우는 **멀티셀러 주문**에서만 발생(셀러가 하나면 아이템을 뭘 고르든 seller/distance가 동일). 이 부분집합에서 두 기준의 일치율은 **1주차 확인 대상**이며, 일치율이 낮으면 1단계 Feature Importance에서 product_category_name의 중요도 해석 시 "대표 아이템 선정 기준의 부작용일 수 있다"는 한계로 명시
> - 정책 적용 후 order_id 유일성 검증 필수

> **geolocation 대표좌표 산출** *(신규 추가)*: geolocation 테이블은 zip_code_prefix 하나에 좌표가 여러 행 존재(약 100만 행 ÷ 약 1.9만 개 prefix ≈ 50행/prefix, 실제 비중은 1주차 확인). 그대로 조인하면 customers·sellers 테이블이 수백만 행으로 불어나므로, **조인 전에 zip_code_prefix별 위도·경도 평균으로 대표좌표 테이블을 먼저 만들고, 그 대표좌표로 distance_km을 하버사인 공식으로 계산한 뒤 customers·sellers에 조인**한다.
>
> **geolocation 미매칭 처리**: 대표좌표 테이블과도 zip 기준 매칭이 안 되는 주문은 distance_km이 계산되지 않음. **동일 주(state) 평균 거리로 대체 + 결측 더미 변수 추가**. 이때 평균은 seller_avg_delay와 동일한 원칙으로 **학습 구간 데이터만으로 계산**함(테스트 구간 정보가 학습에 섞이지 않도록 하는 일반 원칙 — 결측 비중과 무관하게 성립). 실제 결측 비중은 **1주차에 재확인**.

### 4. 데이터 실물 확인

| 행 × 열 | 결측 많은 컬럼 | 이상한 값 | Y 분포 |
|---|---|---|---|
| orders 99,441×8 / reviews 99,224×7 | review_comment_message 58.7% 결측(reviews 테이블 전체 99,224건 기준), order_delivered_customer_date 3.0% 결측 | price 최댓값 6,735(중앙값 74.99), order_reviews order_id 중복 551건(dedup 필요) | review_score 5점 57.8%, 1점 11.5% → 저평점(1～2)=14.7% |

**분석 대상 주문**: order_delivered_customer_date 없는 주문은 1·2단계 모두 제외(같은 모집단 유지). review_id 없는 주문은 2단계에서만 추가 제외.

**3단계 분석 대상 행 수 흐름** *(추가 수정 ⑫)*: 3단계 규칙 문서 §1\~§2 기준. 분석 단위는 주문이 아니라 고유 review_id이다.

| 단계 | 건수 | 설명 |
|---|---|---|
| 분석기간 1단계 Y=0 & 2단계 Y=1 | 8,247주문 | 1점 5,884 / 2점 2,363 |
| 그중 코멘트 있음 (3단계 대상) | 6,449주문 | 8,247주문 기준 코멘트 작성률 1점 81.8%, 2점 69.1%(아래 "1점 77% vs 5점 36%"는 전체 리뷰 기준). 코멘트 없음은 1,798주문 |
| 고유 review_id 기준 (분석 단위) | 6,400건 | 중복 review_id 48개(97주문)를 가장 이른 주문 1건으로 정리 |
| 층화 표본 (손 라벨링) | 310건 | dev 204 / hold-out 106, 분기 × 점수 14개 층 |

**Y 재정의 근거**: 도착 주문의 91.9%가 예상일보다 일찍 도착(오차 중앙값 −12일, 최솟값 −147일), 정확히 예상일 당일 도착은 1.3%에 불과 → 분포가 대부분 음수라 로그변환 불가 → Y를 "지연 여부(조기+정시=0, 지연=1)" 이진 분류로 재정의. 지연 비율은 조기도착 91.9%+정시도착 1.3%를 제외하면 약 6.8%로 소수 클래스임(3절 참조). estimated_delivery_days는 배송오차와의 상관계수(−0.50)·distance_km과의 상관계수(0.52) 양쪽과 상관 있어 X에서 제외(**이 수치는 전체 데이터 기준 — 1주차에 분석 기간으로 재확인**).

**텍스트 관련 확인**: 코멘트 작성률이 1점 77% vs 5점 36%로 편향 있음 → 결합모델 비교는 코멘트 있는 서브셋(**40.6%, 배송완료+리뷰존재 주문 기준**) 안에서만 진행 *(수정: 40.6%가 어느 모집단 기준인지 명시 — reviews 테이블 전체 기준으로 계산하면 41.3%가 나와 혼동 가능했음)* *(추가 수정 ⑩: 1주차 실행 결과 이 모집단 기준 실측값은 40.51% — 이하 5절 이후로는 40.51%를 확정치로 사용)* *(⑪: 3절 3단계 문단도 같은 값으로 정정)*. 저평점 중 약 2/3는 예상일 내 도착(**비지연 주문에서 발생**) → 배송 기반 경보만으로 못 잡는 불만이 존재, 여기가 3단계에서 텍스트가 필요한 지점 *(추가 수정 ⑨: "지연과 무관" → "비지연 주문에서 발생"으로 표현 정정 — 비지연이 곧 배송 관련 불만이 없다는 뜻은 아님)*. 리뷰는 포르투갈어라 **LeIA 사전**을 기본 사용. *(추가 수정 ⑬: 3단계에서는 수동 라벨과 키워드 규칙이 분류의 중심이고 LeIA는 기본이 아닌 보조 도구로 사용 — 근거: 규칙 문서 §9)*

**리뷰 dedup**: order_id 중복 551건 존재 → review_answer_timestamp(설문 발송일이 아닌 실제 응답 시각) 기준 최신 1건으로 dedup. 실제 영향 범위는 **1주차에 재확인**.

**테스트 기간**: 1주차에 월별 지연·저평점 비율 추이를 확인해, 추세적 하락(예: 물류 개선)으로 보이면 초기 기간(2～3개월)을 유지하거나 더 짧게 가져가고, 특정 달만 튀는 들쭉날쭉한 변동이면 표본 부족으로 보고 기간을 확장.

### 5. 수행 계획

- **1주차**
  - 월별 지연·저평점 비율 추이 확인 → purchase_month 처리 근거 + 테스트 기간 확정에 활용
  - **geolocation 대표좌표 테이블 구축**(zip_code_prefix별 위도·경도 평균) *(신규 추가 — 그대로 조인 시 행 폭발 방지를 위한 선행 작업)*
  - SQL 조인·마스터 테이블 구축(geolocation 대표좌표, 카테고리 번역표 포함), order_reviews dedup(review_answer_timestamp 기준), order 단위 집계(3절 정책 적용: price·freight 합산 / category=가격최대 아이템 / seller·distance=거리최대 아이템 / installments=전체 레코드 최댓값) 후 order_id 유일성 검증
  - 데이터 의존적 기준값 확정: seller_avg_delay 최소 주문건수 기준, product_category_name 상위 N 기준, geolocation 미매칭 실제 비중(대표좌표 기준), 카테고리 대표 지정 기준 간 일치율(멀티셀러 주문 내)
  - 파생변수 생성: 지연 여부(Y, 날짜 기준), distance_km(하버사인 공식, 미매칭은 학습구간 주 평균 + 결측 더미), seller_avg_delay(지연 비율), product_category_name(상위 카테고리+미상), purchase_month(1\~12 또는 성수기 더미)
  - EDA 통계검정: 지연/정시 간 review_score T-test, 카테고리×저평점 카이제곱 독립성 검정(검정 전 카테고리 묶기 완료)
  - X 변수 간 상관관계 확인(Feature Importance 해석 시 참고용), estimated_delivery_days 관련 상관계수 분석 기간 기준 재확인
  - **1단계**: 로지스틱회귀→RF Classifier, Feature Importance로 지연과 연관된 변수 파악(인과관계가 아닌 예측 기여도로 해석), TimeSeriesSplit+하이퍼파라미터 튜닝, 시간 기준 분리, class_weight='balanced' 적용 및 혼동행렬/PR-AUC로 성능 보고(근거는 3절 참조)
  - **2단계**: 동일 방식으로 저평점 여부 예측. 저평점 비율(14.7%)은 1단계 지연 비율(6.8%)만큼 극단적이지 않으므로 class_weight='balanced' 적용 여부는 1단계 결과를 그대로 따르지 않고 별도로 검토(불균형이 완만하면 미적용, 성능 저하 시 적용) 후 결정. 혼동행렬/ROC·PR-AUC + 베이스라인 대비 개선폭 평가
  - 1단계 지연 연관 변수가 2단계 변수중요도에서도 상위인지 대조 (겹치면 지연이 저평점의 공통 경로 중 하나라는 뜻이고, 안 겹치면 두 단계가 서로 다른 메커니즘으로 저평점을 만든다는 뜻 — 3단계에서 다룰 "배송과 무관한 저평점"과 연결됨. 단, 두 단계는 모집단이 다름(2단계는 4절에서 명시한 대로 review_id 없는 주문을 추가 제외하므로 1단계보다 표본이 작음) — 대조 결과 해석 시 이 표본 차이를 감안해야 함. 실제 서비스에 쓰이는 조기경보 모델은 2단계이며, 1단계는 지연과 연관된 변수를 파악하는 탐색적 분석)

- **2주차**
  - 3단계 대상(1단계 Y=0 & 2단계 Y=1 & 코멘트 존재) 추출 → 리뷰 코멘트 읽고 불만 원인 분류(필수)
  - (선택) 코멘트 서브셋 내에서 정형 단독 vs 정형+텍스트 결합모델 성능 비교, 결론은 "사후 설명력"으로 한정
  - (선택) 셀러 군집(3～4개 세그먼트)

- **3주차**
  - 결과 정리 및 강사 피드백 반영
