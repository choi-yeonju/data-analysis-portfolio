# 강사님 보고 안건

## 1. 한 줄 결론

1단계(지연 예측)는 전체로는 약한 신호가 상위 일부에만 있고(로지스틱만 기저율과 구분되고 RF는 구분되지 않음) 이는 2018-08의 신호 역전에 크게 좌우됩니다(8월 제외 시 1.32~1.57배, 사후 분석). 2단계(저평점 예측)는 월별로 일관된 약한 신호가 있지만 단일 변수 `freight_sum`이 기저율 위 초과분의 약 79%를 재현합니다. 시간 분할, 시간순 CV 튜닝, 단일 변수 기준선까지 거친 뒤에도 같은 결론이라, 1단계는 모델 변수 중요도 대신 월별·지역별 기술통계로 설명하는 방향을 제안합니다.

- F1 최대 임계값은 신호가 약해 거의 전부를 경보로 잡습니다(표시 비율 51~90%). 혼동행렬 대신 PR-AUC와 상위 10% 리프트(1.3~1.6)로 보고합니다. 리프트의 신뢰구간은 계산하지 않았습니다.
- 모델 입력 변수의 다중공선성은 문제가 없습니다(VIF 최대 1.80, 카테고리 더미 포함).
- 단일 변수 기준선은 수치 후보 중 학습 CV 최고 변수입니다(1단계 후보 2개 `distance_km_filled`·`seller_avg_delay`, 2단계 5개). 그래서 1단계의 "단일 변수 대비"는 2단계보다 약한 기준입니다.

## 3. 원인 진단 (1단계) — 갱신

1. **셀러 변수:** 합산 AUC에 시기 효과가 섞여 있었습니다. fallback 행끼리 같은 달 안에서 비교하면 0.624가 0.514로 떨어집니다. 시기를 걷어낸 셀러 신호는 학습 0.561, 테스트 0.545로 약하게 남습니다.
2. **distance:** 월 내 AUC가 학습 0.61에서 테스트 0.47로 바뀌었고, 2018-08은 0.31로 뒤집혔습니다.
3. **2018-08 역전의 원인 (6-10, 6-11):**
   - 8월 양성 393건 중 335건(85%)이 8/1~14에서 나왔고, 이 구간에서 0~100km late율이 20.0%(5~7월 3.3%)로 뛰었습니다. **역전의 주원인은 8월 초 근거리 지연 급증입니다.**
   - 이 급증은 **예상소요일 단축과 함께 나타났고, 첫 주에는 실제 배송 지연도 겹쳤습니다.** 상파울루 내(대표 셀러 기준) 7월과 8월 첫 두 주를 비교한 결과입니다(late는 도착일이 예상일보다 늦은 것이므로 예상일과 실제 소요일을 함께 봐야 합니다).

     | | 7월 (n=2,040) | 8/1~7 (n=752) | 8/8~14 (n=629) |
     |---|---|---|---|
     | 예상소요일 중앙값 | 13.06일 | 7.45일 (−5.60 [−5.84, −4.94]) | 8.35일 (−4.71 [−5.04, −3.88]) |
     | 실제 소요일 중앙값 | 5.08일 | 6.01일 (+0.93 [+0.71, +1.14]) | 5.17일 (+0.09 [−0.11, +0.42], 0 포함) |
     | 실제 소요일 p90 | 10.19일 | 11.17일 (+0.98 [+0.36, +2.05]) | 10.03일 (−0.16 [−1.08, +0.42], 0 포함) |
     | late율 | 4% | 22% (+17.47%p [+14.59, +20.63]) | 8% (+3.88%p [+1.68, +6.13]) |

   - **두 주 비교:** 예상일은 두 주 모두 5일 안팎 짧았지만 실제 소요일 증가는 첫 주에만 있었고, late율은 22%와 8%로 갈렸습니다(8/1~14로 합치면 15%로 이 차이가 가려집니다).
   - **예상일 단축의 역할:** 실제 소요일이 7월 수준이었던 둘째 주에도 late가 4%에서 8%로 올랐으므로(+3.9%p [+1.7, +6.1]) 예상일 단축이 지연에 취약하게 만든 조건으로 작용했을 가능성이 큽니다. 6→7월은 실제 소요일이 같은데(중앙값 5.10 → 5.08일) 예상일이 약 6일 줄고 late가 1%에서 4%로 올라 예상일 효과와 부합하고, 5→7월(평균 기준)만 실제 소요일 감소(7.3 → 6.1일)가 섞여 가리지 못합니다. 첫 주의 22%는 여기에 실제 지연(+0.93일)이 겹친 것으로 봅니다.
   - **반사실(6-12, 모든 주문을 같은 일수 옮기는 단순 근사):** 예상일을 7월 수준으로 되돌리면 late가 8/1~7은 약 22%에서 3.3%, 8/8~14는 약 8%에서 2.2%로 내려가고(+4~+6일 적용 시 8/1~7은 3~7%, 8/8~14는 2~3%, 노트북 밖 근사), 실제 소요일을 7월 수준으로 되돌려서는 16.1%, 7.9%로 거의 변하지 않습니다.
   - **7/30~31 직접 근거(6-12):** 급증이 시작된 7/30~31은 예상일이 8.05일로 이미 짧고 실제 소요일은 3.99일로 7월(5.08일)보다 빨랐는데 late가 12.8%였습니다.
   - **한계:** 예상일 쪽 효과가 크게 나타나지만 기여 비중은 확정할 수 없습니다(7월 예상일을 5일 줄이는 단순 적용은 첫 주는 재현하나 둘째 주는 재현하지 못해 둘째 주의 단축은 균일하지 않았습니다). 둘째 주는 실제 p90 차이(−0.16 [−1.08, +0.42])가 7월과 구분되지 않아 절단 신호는 없어 보이지만 작은 절단은 배제하지 못합니다(뚜렷한 절단은 8/15~31). 일별로는 8/7(약 33%)까지 높다가 8/8(약 9.5%)에 급락했습니다(노트북 밖 원본 CSV 근사).
   - **예상일을 왜 줄였는지, 첫 주에 실제로 느려진 원인, 라벨 기준 변화가 지연 급증의 몇 %를 설명하는지는 모릅니다.**
   - 8/15~31은 300km 이상 late율이 0.0~0.5%이고 1000km 이상 비중이 15.9%에서 8.3%로 절반이 됩니다. 8월 말 주문 자체가 줄어드는 형태(base 전체 일별 주문 8/22 185건 → 8/29 11건, 상파울루 내 마지막 주 실제 소요일 2.1일)로 우측절단·생존표본 편향의 흔적이 보입니다. 다만 이 구간 양성이 58건뿐이라 역전 전체에 대한 기여는 작고, 후반부의 낮은 late율을 "개선"으로 읽으면 안 됩니다.
4. **CV와 테스트의 어긋남:** 1단계는 CV에서 단일 변수(1.47)가 선택 모델(1.35~1.42)보다 높았는데 테스트에서는 로지스틱이 단일 변수보다 높아 순위가 바뀝니다. 8월을 제외하면 테스트가 1.32~1.57배로 CV 수준에 가까워지지만 이 순위 차이는 8월을 빼도 남습니다. CV가 시기 효과로 부풀었는지는 이 비교로는 확인되지 않습니다. 2단계는 선택된 설정의 CV가 1.38~1.42배, 테스트가 1.35배로 거의 일치합니다.

## 5. 한계

- fallback 값은 시간만의 함수라 시기 대리변수로 작동합니다. "배송이 끝난 주문만" 쓰는 규칙 때문에 초반(2017-01~05)과 late 급증 직후 값이 실제 누적보다 낮게 편향됩니다(격차 최대 약 0.027, 테스트 구간은 0.004 이하).
- **late 라벨이 예상일에 의존하는데 8월에 예상일이 짧아졌습니다.** 라벨 기준의 시간 일관성이 1단계의 한계입니다(6-11은 상파울루 내, 두 구간 비교, 분포 기반이며 독립 가정으로 구간이 좁습니다).
- 테스트 4개월 중 8월 한 달이 1단계 합산 성능을 끌어내립니다(8월 0.67~0.77배, 8월 제외 시 1.32~1.57배). 테스트 구간은 바꾸지 않았고, 8월 제외 결과는 사후 "민감도 분석"으로만 표기했습니다.
- 8월 후반 우측절단이 전체 late율에 미치는 영향은 +0.21%p로 판단 기준(0.3~0.5%p) 미달이라 테스트 구간을 유지했습니다. distance 관계에 대한 영향은 6-10에서 별도로 확인했습니다.
- 지연과 저평점의 연결(저평점률 62.4% vs 9.2%)은 리뷰 응답 시점을 통제하지 않은 미조정 비교입니다. 도착 후 응답만 보면 19.5% vs 9.2%(2.1배)입니다.
- 선택된 설정이 그리드 가장자리(로지스틱 C=0.01, RF depth 4)입니다. 테스트를 본 뒤라 그리드를 넓히지 않았습니다.
- 부트스트랩은 다중비교 보정이 없고, 로지스틱 개선을 만드는 변수 조합은 분해하지 않았습니다.
- 테스트 구간은 설정 선택에는 쓰지 않았지만 2~6절 진단(월별 AUC, ablation, 8월 분해)에서 여러 번 확인했고, 8월 역전은 테스트를 본 뒤 알게 된 사실입니다.
- 2018-02~03 스파이크 원인은 미상입니다.
- 주 단위 분할(8/1~7, 8/8~14)은 일별 late율을 본 뒤 정한 사후 탐색이며 구간이 실제보다 좁습니다. 7월 기준(late 4.1%)에는 급증이 시작된 7/30~31(12.8%)이 포함돼 7/1~29(3.0%)보다 높게 잡혔고(6-12), 기준을 7/1~29로 하면 차이는 더 커지므로 결론은 같습니다(8월 제외 민감도에서도 7/30~31은 7월 쪽에 남습니다).
- 최종 학습/테스트 분할에는 gap이 없어 학습 행의 3.95%가 5/1 이후 도착 라벨을 포함하나 영향은 0.02 이내입니다(2절).
- "사전 고정"으로 적은 규칙(CV 튜닝, 판정 기준)은 작성자 기록이며 Day 6 작업에 커밋 이력이 없어 시점을 증명하지 못합니다. 3단계부터는 규칙을 먼저 커밋한 뒤 실행하겠습니다.
- `MIN_POS=100`은 결과를 본 뒤 정한 진단용 기준입니다.

## 6. 강사님께 여쭙고 싶은 것

1. 테스트 구간 4개월 중 한 달(8월)이 1단계 결과를 좌우하는데(월별·8월 제외 결과는 7-9), 구간 유지에 8월 제외 민감도 병기로 충분한지, 월별 롤링 평가를 더해야 하는지
2. 1단계 설명을 모델 중요도에서 월별·지역별 기술통계로 옮겨도 되는지(계획 변경으로 보시는지). 1단계는 효과 크기가 작고 8월 역전으로 불안정한데, 8월 제외 5~7월 구간에서 permutation 중요도를 보조로 보는 방안은 어떨지도 여쭙고 싶습니다
3. late 라벨이 예상일에 의존하는데 8월에 예상일이 짧아졌습니다. (a) 이를 한계로만 기록해도 되는지, (b) 예상소요일은 주문 시점에 알 수 있어 시점 누수는 아니지만 late 정의에 쓰여 계획서가 X에서 제외했는데, X 후보로 재검토해야 하는지(계획 변경 사항). (c) 예상일 정책이 바뀐 시기에 late 라벨이 흔들리므로, 실제 소요일 기준으로 보조 정의한 Y를 병행해 보는 것은 어떤지(계획 변경 사항). 1단계 X에 넣으면 late 정의에 쓰이는 값이 입력에 들어가 해석이 달라지고, 2단계 조기경보 입력으로는 주문 시점에 알 수 있어 사용할 수 있습니다
4. 2단계는 `freight_sum` 단독이 신호의 대부분(기저율 위 초과분의 약 79%)인데, 이를 근거로 2단계 해석을 어떻게 잡는 게 좋을지
5. 계획서에서 `estimated_delivery_days`와 배송오차의 상관계수를 "−0.50"으로 적었을 때 주신 코멘트("오차 −0.5는 표기 오류로 보입니다")가 표기 자체의 오류인지 문구의 모호함인지 취지를 확인하고 싶습니다
